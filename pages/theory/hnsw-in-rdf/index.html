Implementing HNSW in RDF

Most databases treat vectors and graphs as separate systems. Loka stores vector embeddings as typed RDF literals (loka:f32vec) and exposes HNSW neighbor connections as virtual triples — making the vector index queryable by the same SPARQL engine that traverses relationships.

Three Layers, One Graph
Data triples: regular RDF relationships (:discusses, :author).
Vector triples: embeddings stored as typed literals (:hasEmbedding "..."^^loka:f32vec).
HNSW triples: neighbor edges generated on-the-fly from the HNSW index (loka:hnswNeighbor).
Example Triple
:paper_42 :hasEmbedding "0.23 -0.11 0.87 ..."^^loka:f32vec .

SELECT ?similar ?topic
WHERE {
  :paper_42 loka:hnswNeighbor+ ?similar .
  ?similar :discusses ?topic .
}
Why This Matters
The HNSW index is the 4th index type alongside SPO/POS/OSP. SPARQL property paths can traverse loka:hnswNeighbor+ just like :hasFather+. The query planner decides whether to use HNSW or triple indexes based on cost — no separate vector database API needed.
